## Resume-after-login for the daily Lectio walk

User asked: when the app prompts for login mid-Lectio, keep all status so the
reader returns to the step they were at.

**Diagnosis:** `returnTo` already brought the browser back to the right page
(`/today/meditatio`), but an anonymous walk leaves no `daily_sessions` row, so
the first post-login page load created a fresh session at `silencio` and
`canOpenStep` bounced the reader back to `/today/silencio`. The lost "status"
was the reached step, not the URL.

**Fix:** signed `anon_progress` cookie (HMAC via SESSION_SECRET, same pattern
as `pending_draw`):

- `src/lib/anonProgress.ts` — `recordAnonProgress(cookies, day, step)` writes
  `{v:1, day, step}` signed, 7-day TTL; `takeAnonProgress(cookies, day)` reads
  + clears, day-matched, signature-checked (can't forge a skip-ahead).
- `today/[step].astro` — anonymous readers record the step on every page load
  (only silencio/lectio render for them); a freshly signed-in reader's first
  `ensureSession` seeds `reached_step` from the cookie, then the cookie is
  cleared.
- `today/index.astro` — same seeding on the entry page.
- `dailySession.ensureSession` — new optional 5th param `seedStep` used only on
  INSERT (ON CONFLICT DO NOTHING keeps existing rows untouched).

Covers email login, signup, and Google OAuth with one mechanism since the
cookie just survives the auth round-trip. Draft text needs no preservation:
anonymous readers never see a writing form (the wall is a GET redirect).

Tests: new `anonProgress.test.ts` + 2 seeding cases in `dailySession.test.ts`.
