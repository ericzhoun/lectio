## Resume-after-login for the daily Lectio walk

User asked: when the app prompts for login mid-Lectio, keep all status so the
reader returns to the step they were at.

**Diagnosis:** `returnTo` already brought the browser back to the right page
(`/today/meditatio`), but an anonymous walk leaves no `daily_sessions` row, so
the first post-login page load created a fresh session at `silencio` and
`canOpenStep` bounced the reader back to `/today/silencio`. The lost "status"
was the reached step, not the URL.

**Fix:** signed `anon_progress` cookie (HMAC via SESSION_SECRET, same pattern
as `pending_draw`):

- `src/lib/anonProgress.ts` — `recordAnonProgress(cookies, day, step)` writes
  `{v:1, day, step}` signed, 7-day TTL; `takeAnonProgress(cookies, day)` reads
  + clears, day-matched, signature-checked (can't forge a skip-ahead).
- `today/[step].astro` — anonymous readers record the step on every page load
  (only silencio/lectio render for them); a freshly signed-in reader's first
  `ensureSession` seeds `reached_step` from the cookie, then the cookie is
  cleared.
- `today/index.astro` — same seeding on the entry page.
- `dailySession.ensureSession` — new optional 5th param `seedStep` used only on
  INSERT (ON CONFLICT DO NOTHING keeps existing rows untouched).

Covers email login, signup, and Google OAuth with one mechanism since the
cookie just survives the auth round-trip. Draft text needs no preservation:
anonymous readers never see a writing form (the wall is a GET redirect).

Tests: new `anonProgress.test.ts` + 2 seeding cases in `dailySession.test.ts`.
277/277 pass. `astro check`: only pre-existing error remains
(`scripts/tts/lib.mts:174` writeFileSync arity — part of the uncommitted TTS
work), plus a pre-existing ts(6133) hint on `[step].astro` returnTo (verified
it fires on HEAD too via stash round-trip).

## First-party analytics + A/B testing instrumentation

Built a self-hosted analytics & A/B framework on the existing Cloudflare stack (no third-party scripts):

- `src/lib/ab.ts` — experiment registry, deterministic FNV-1a assignment from visitor id, `ab` cookie parse/serialize. Starter experiment: `signup_cta_copy` (control vs "invitation" CTA in LoginForm).
- `src/middleware.ts` (new) — mints `vid` cookie (UUID, 2y) and assigns variants on every request; exposes `Astro.locals.vid/variants`.
- `src/lib/analytics.ts` — `analytics_events` D1 table (lazy ensure, WeakSet per-db), allowlisted client events, `ingestClientEvents` (batch cap 25), `trackServerEvent` for signup_success/login_success/checkout_start.
- `src/pages/api/analytics/collect.ts` — beacon endpoint, always 204.
- `src/scripts/analytics.ts` — page tracker: auto page_view, `[data-event]` click + `[data-event-form]` submit delegation, batched sendBeacon; global `window.lectioTrack(name, props)`.
- Wired: nav Today/Pricing links, auth signup link, login overlay open, step-page audio players (passage/clip/guided), pricing checkout forms.
- Tests: ab.test.ts (12), analytics.test.ts (5) using D1Memory (added `batch()` to the helper). Full suite 294 passing, astro check 0 errors.

To read results: query `analytics_events` in D1, group by `variants`. New experiments = add to `EXPERIMENTS` in ab.ts; re-bucketing is automatic.
