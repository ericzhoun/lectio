
## enjoyhim.org "high requests" investigation (main session)
- Zone gets 900–7,650 req/day but app has only 3 registered users, 2 daily invitations ever.
- Root causes: (1) lectio worker's own podcast-feed subrequests counted in zone analytics — fetch + cache.put to www.abidingway.life/lectio-podcast appear as GET/PUT-204 rows in zone analytics (~18% of sampled traffic; Squarespace 404s real PUTs so the 204s are internal Cache API writes); feed cached only 1h per colo → ~300 GETs + ~40 cache writes/day; 82 sampled 504s when Squarespace is slow → retries per page render. (2) crawler + vuln-scanner waves on the new site (/aws.yml, /.docker/secrets.json, /aws/s3/credentials, /config/stripe.yaml, ?rest_route=/batch/v1, /api/auth/google/start 302-probing; DE/GB/SG/BE/PL data-center IPs; Sep 23 16:00 UTC spike 4× typical). (3) no-store HTML + /today 302 + multi-step flow multiplies requests per visitor.
- Suggested fixes: longer feed TTL or cron→KV prefetch, negative caching on feed failure, Bot Fight Mode + WAF rule for scanner paths. Worst day 7.6k ≪ 100k/day free Workers limit.
