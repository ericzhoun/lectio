## LoginOverlay 弹窗可视区域修复（Amen → 我已有账户）

用户反馈：Amen 步骤点击"我已有账户"弹出的登录窗口应在浏览器当前可视区域内。

排查结论（`src/components/LoginOverlay.astro`，点击 `/login` 链接被拦截后 `showModal()` 弹出 `<dialog>`）：

1. 弹窗定位完全依赖 UA 默认样式（无 author 规则）。桌面 Chromium 下居中正常（实测 1280×800 完美居中），但 computed position 是 `absolute`，在没有 top-layer 正确支持的浏览器/WebView 里会锚定到文档顶部——长页面滚到底部点击后弹窗整个在视口外。
2. 短视口下有实际 bug：弹窗 `max-height: 100dvh - 40px` 压缩到 350px，但表单内容 438px，`overflow` 默认 visible → 底部 88px（提交按钮区域）溢出到视口外且完全无法触达（844×390 实测）。

修复：dialog 显式 `position: fixed; inset: 0; margin: auto;`（视口锚定居中，不依赖 top-layer）+ `overflow: auto`（内容超高时弹窗内部滚动，全部可达）+ `max-height` 加 `100vh` 回退行。

验证：静态复现页 + 真实页面，4 种视口（1280×800 / 1280×600 / 844×390 / 390×844）全部 `dialogInsideViewport: true`，横屏下提交按钮可滚动到且可见。524 个测试全过。

## 本机开发环境教训（重要）

- `astro dev` 在这台机器只绑定 IPv6 `[::1]:4399`，`127.0.0.1` 连不上；浏览器要用 `http://[::1]:4399` 或 `localhost`。
- **dev server 会反复"假死"：所有请求变成 200 + 空 body（curl 显示 `200:0`）**。用 `curl -s -o /dev/null -w "%{http_code}:%{size_download}"` 探测，size 为 0 就要杀掉重启（9229/4399 端口的进程树 `taskkill //F //T`）。
- ZCode 内置浏览器（IAB）两个怪癖：a) 带 302 重定向的导航常落到空文档（`chrome-error` 或 39 字节空 html），直接 `goto` 最终 URL 可绕过；b) 跨 JS 调用 `tabs.get()` 重新绑定旧标签页后文档常变空，**每次都用 `browser.tabs.new()` 新开标签页最稳**。
- 走完六步到达 Amen 的捷径：加载任意 today 页后，在页面内用 `fetch` 发同源表单 POST（meditatio/oratio/actio 三步）+ GET contemplatio，再 `goto /today/amen`。相同文本重复提交不会重复烧 AI 调用（dailySubmit 有 unchanged-resubmit 短路）。
- 不稳定的页面验证可以做成静态复现页（dev HTML 的 `<style>` 是内联的，把 dialog 标记+样式抽出来配上 python http.server 即可），弹窗定位是纯 CSS，行为完全一致。
