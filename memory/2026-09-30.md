## D1 visits data analysis (database b31145ba-04a6-4fc9-bc01-744f1224e3d8)

Analyzed Sep 6–30 traffic from `analytics_events` (client-side, 991 events / 257 visitors) and `daily_sessions` (server-side, 2,590 rows).

Key findings:
- Two data sources disagree 10×: client analytics saw 257 visitors, server-side sessions 2,303 distinct guest ids — most server traffic is crawlers (no JS). Sep 26 spike = 164 single-pageview JS visitors crawling every `/library/*` page evenly (2 views each).
- `daily_sessions` pollution: 1,922 rows have `day='verse:<slug>'` (by-design pseudo-day for library walks, but crawlers hit those URLs), 160 rows are future liturgical dates (Advent/Christmas/Epiphany/Easter URLs). Only ~508 real-date rows, 8 completed ever.
- Real human scale: ~93 JS visitors excl. crawl day; 78 one-day only, 15 returned 2+ days; 3 signups ever (last Sep 9), 3 subs.
- Funnel: 64 landed on `/` → 12 clicked hero CTA (hero_begin = 41/51 of all cta_clicks) → 18 started /today/silencio → 13 lectio → 10 meditatio → 6 oratio → 5 actio → 5 amen. ~28% of starters finish.
- Audio is stickiest feature: 96 plays by 16 visitors. Chat dead (7 messages ever). Drawing stopped Sep 16. daily_invitations empty (email loop never fired).
- zh = 45% of views. Peaks 21–01 UTC + 04–05 UTC.
- A/B signup_cta_copy: control 6.7% vs invitation 5.4% visitor click rate — underpowered, no signal.

Top recommendations given: bot-filter both analytics write paths; add referrer/UA/country columns; cut homepage→start friction; progress indicator + time expectation during walk; move signup ask to post-amen peak (claimGuestWalk already supports); launch the email reminder loop; stop the copy A/B.
