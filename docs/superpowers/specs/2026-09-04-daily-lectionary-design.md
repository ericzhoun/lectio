# Daily Lectionary Reading - Design

Date: 2026-09-04
Status: Approved, ready for implementation planning

## Summary

Add a dated daily reading, staged step by step through the six movements of Lectio Divina
(Silencio, Lectio, Meditatio, Oratio, Contemplatio, Actio), ending in a written intention.

Today the app is question-driven: the visitor asks a question, verses are drawn at random from a
148-verse deck, and the model relates the verses to the question. That flow stays exactly as it is.
The daily reading is a fourth mode beside the three spreads, and it is not question-driven - every
user gets the same passage on the same day, and the model responds to what the user writes rather
than to a question asked up front.

Two problems motivate it. First, a random draw invites a divination reading of the product, which
the project explicitly rejects; a dated liturgical passage removes the ambiguity. Second, nothing
in the current product gives a reason to return at the same time tomorrow.

## Goals

- A passage for each calendar day, identical for every user, from a real liturgical calendar.
- Six staged steps, one screen at a time, with visible progress and correct resume.
- The user writes at Meditatio, Oratio and Actio; the model responds to their words.
- Free and ungated for signed-in users, every day.
- Both supported languages (`en`, `zh`), on public-domain scripture only.

## Non-goals

- Replacing or altering the existing deck, spreads, library, or entitlement model.
- Audio (tracked separately, on the `add-audio` branch).
- Streaks, badges, notifications, or any missed-day guilt mechanic.
- Rosary, adoration, multi-lesson programs.

## Decisions

| Decision | Choice | Why |
|---|---|---|
| Placement | Fourth mode, existing draws untouched | No regression risk; the two flows answer different needs |
| Passage source | Revised Common Lectionary, shipped as generated static data | Freely redistributable references, no runtime dependency, no license risk, works in both languages |
| Model's role | Responds to what the user writes at each step | The differentiator over hand-authored competitors; makes Actio journalable |
| Access | Free and ungated for signed-in users | It is the habit loop; paid tiers keep owning the question-driven spreads |
| Staging | One URL per step, server-rendered | Matches the codebase's POST-and-redirect idiom; linkable, back-button-correct, free resume |

## Architecture

### Lectionary data

New `src/lib/lectionary.ts` plus generated `src/lib/lectionaryDays.json`, committed like
`bibleChapters.json`. Entry shape:

```jsonc
{ "2026-09-04": {
    "season": "ordinary", "week": 22, "weekday": "friday",
    "title": { "en": "Friday, Week 22 in Ordinary Time", "zh": "常年期第二十二周 星期五" },
    "readings": { "first": "Col 1:15-20", "psalm": "Ps 100", "gospel": "Luke 5:33-39" },
    "focus": "gospel" } }
```

Generated by a new `scripts/build-lectionary.mjs` from the RCL tables and a computed Easter date,
covering a rolling window of at least four years. The generator must be deterministic: identical
inputs produce byte-identical output, so regeneration never yields a spurious diff.

`focus` names the single passage the six steps walk. One passage per day, not three - three would
make the session too long and the model's context mushy. The other readings appear as "also read
today" links and nothing more.

### Passage text

References resolve through the existing getbible-derived chapter data (WEB for `en`,
和合本 for `zh`). `bibleChapters.json` currently covers only chapters touched by the deck, so
`scripts/fetch-bible-context.mjs` gains a second input: the chapters the lectionary window needs.

Check the resulting file size before committing to a bundled import. If it exceeds a few megabytes,
chapter text moves to a KV lookup instead. That is a small change now and an expensive one later.

### "Today"

Computed in the user's timezone, never the Worker's UTC. The zone comes from a cookie set by client
JS on first visit and is validated against `Intl.supportedValuesOf('timeZone')`; anything unknown or
unparseable falls back to UTC. A day boundary that flips at the wrong local hour quietly ruins a
daily-habit product.

### Routes

`/today` is the only entry point users see. It resolves the local day, ensures a session row, and
redirects to the furthest incomplete step.

Steps live at `/today/[step]` for `silencio | lectio | meditatio | oratio | contemplatio | actio`,
with `/today/amen` as the closing summary. A GET renders the step; its form POSTs to itself, saves,
and redirects to the next step.

Every step enforces one guard: a user may open any step at or before their furthest reached one,
and jumping ahead redirects back. This keeps someone from landing on Oratio having never read the
passage, and keeps the progress indicator honest.

### Session state

Self-creating tables, following the `ensureTable` pattern in `src/lib/db.ts`:

```sql
CREATE TABLE IF NOT EXISTS daily_sessions (
  user_id TEXT NOT NULL,
  day TEXT NOT NULL,              -- 'YYYY-MM-DD', the user's local day
  lang TEXT NOT NULL,
  reached_step TEXT NOT NULL DEFAULT 'silencio',
  completed_at DATETIME,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, day)
)
```

```sql
CREATE TABLE IF NOT EXISTS daily_step_entries (
  user_id TEXT NOT NULL,
  day TEXT NOT NULL,
  step TEXT NOT NULL,
  user_text TEXT NOT NULL,
  ai_text TEXT,
  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  PRIMARY KEY (user_id, day, step)
)
```

Writes are upserts on the primary key, so resubmitting a step edits it rather than duplicating it.

`lang` is pinned when the session is created. Switching language mid-session would strand the user's
own words beside a different translation.

## The six steps

| Step | Input | Model | Notes |
|---|---|---|---|
| Silencio | none | no | Timed still screen, 60s default, skippable. Their 5 min is too long unprompted |
| Lectio | none | no | The passage, read twice, with an A- / A / A+ size control |
| Meditatio | textarea | yes | Passage stays on screen. "What word or phrase caught you?" |
| Oratio | textarea | yes | Their Meditatio words held above the box; what they want to say to God |
| Contemplatio | none | **no** | A timer and their own words from Oratio. Deliberately generates nothing |
| Actio | textarea | yes | "One thing you'll do today." Completing it marks the session done |

Contemplatio having no model output is a deliberate design constraint, not an omission. Resting
wordlessly is the step; filling it with generated text would defeat it.

## Anonymous visitors

Silencio and Lectio are open to anyone. Meditatio prompts sign-in, since the user's writing needs an
account to belong to. Reuse `LoginOverlay.astro` and the `pendingDraw` return-path pattern so the
visitor lands back on Meditatio after authenticating rather than on the homepage.

## Model contract

New `src/lib/dailyReflection.ts`, beside `openai.ts` rather than inside it. The existing
`generateInterpretation` is built around a question, spread positions and a `cards[]` array; a single
conversational reply does not fit that shape. Same client, same model, same strict-JSON discipline.

```ts
export async function generateStepResponse(input: {
  step: 'meditatio' | 'oratio' | 'actio';
  passage: { ref: string; text: string };
  userText: string;
  priorSteps: { step: string; userText: string }[];
  lang: Lang;
}): Promise<{ text: string }>
```

One call per submitted step, three per completed session. `priorSteps` carries the user's own earlier
words so Oratio knows what struck them at Meditatio. That continuity is the point, and it stays cheap
because it is their text, not a transcript.

Per-step system prompts share a base that inherits the existing guardrails: warm and hopeful, never
predictive, never citing scripture outside the passage given, written in the user's language.

- **Meditatio** - reflect back what they noticed and open it one turn deeper. Never tell them what
  the passage "really means." 2-3 sentences.
- **Oratio** - receive what they said to God. Do not answer on God's behalf; this failure mode would
  wreck the product's credibility. Affirm, and at most offer words for something they seemed to be
  reaching for. 2-3 sentences.
- **Actio** - take their intention seriously; make it concrete and small if it is vague.
  1-2 sentences, never a homework list.

`max_completion_tokens` around 200. The user's words should outweigh the model's on every screen.

### Failure handling

Unlike the draw flow, which surfaces an error string in `summary`, a failed model call here **still
saves the user's text and still advances the step**. `ai_text` stays null and the page renders the
step's static prompt instead. Losing a prayer because the API returned a 500 is unacceptable; losing
the model's comment is not. A null `ai_text` is a normal renderable state, not an error state.

### Safety

Users will write real distress into these boxes. The base prompt instructs the model to stay
pastoral, avoid diagnosis, and - where someone signals crisis - respond gently and surface the
existing help affordance rather than attempting to counsel.

### Cost

Three completions of roughly 200 tokens per user per day, comparable to a single existing Deep Lectio
reading. Consistent with leaving the flow ungated.

## History

`/history` lists daily sessions alongside draws. A completed day is re-readable at
`/today/amen?day=YYYY-MM-DD`. The user's own words are the part worth keeping.

## Edge cases

- **Day rollover mid-session** - the day is fixed when the session is created and carried in the row,
  never recomputed per request. A session begun at 23:55 stays on that day.
- **Missed days** - no backfill, no guilt UI, no broken-streak messaging. `/today` is always today.
  Past days are readable from history but not resumable.
- **Date outside the generated window** - the page must not 500. It falls back to a fixed seasonal
  passage and logs loudly. A CI check fails the build when fewer than 180 days of window remain, so
  regeneration is scheduled rather than reactive.
- **Invalid timezone cookie** - validated against `Intl.supportedValuesOf('timeZone')`, falling back
  to UTC.
- **Double submit** - step POSTs are idempotent upserts. The model call is skipped when `ai_text`
  already exists and `user_text` is unchanged.

## Testing

Following the existing `src/lib/__tests__` and vitest setup: no live network, `cloudflare:workers`
mocked.

- `lectionary.test.ts` - date to liturgical day across a full year, Easter-dependent boundaries,
  year A/B/C rollover at Advent, the missing-date fallback, and that every reference in the shipped
  file resolves to real text.
- `dailySession.test.ts` - the furthest-step guard rejects jumping ahead and permits revisiting;
  upserts edit rather than duplicate; the day stays pinned across rollover.
- `dailyReflection.test.ts` - prompt assembly per step, prior-step continuity, and the critical case:
  a thrown OpenAI error still saves `user_text` and still advances with a null `ai_text`.
- A route-level test for the anonymous gate at Meditatio, mirroring `auth-login-route.test.ts`.
- A generator determinism test: identical inputs produce byte-identical output.
