How it works

Checkout grants the trial

/api/stripe/checkout adds subscription_data.trial_period_days = 30 for monthly billing — but only if the account's subscription row has no stripe_subscription_id (never subscribed before). Stripe collects the card, charges nothing.

Webhook snapshots real state

Trial subscriptions start as trialing, and Stripe may send customer.subscription.created before checkout.session.completed. The handler now maps created events and retrieves the subscription on checkout completion, storing the true status and trial-end date immediately.

Trial users get full plan access

tierFromSubscription() treats active and trialing alike: a trialing Basic user can draw 20×/day with 3-card spreads; Pro is unlimited. past_due / canceled still fall back to free.

Trial ends automatically

Stripe fires customer.subscription.updated at trial end — status becomes active (card charged) or past_due (card failed). The existing webhook path updates the row; no new events or cron jobs needed.

Decisions & guardrails

In scope

  • Trial on monthly Basic & Pro checkouts
  • One trial per account (local row guard — cancelled subs keep their stripe_subscription_id via COALESCE upsert)
  • Event-order-proof webhook (created + completed snapshot)
  • No DB schema changes — status column already stores trialing

Out of scope / known limits

  • No trial on annual plans (already discounted 40%)
  • Cross-account re-trials (needs Stripe customer history search)
  • Trial length is a code constant, not an env var
